# 远程 Release 同步工具

这是一个基于 `Qt Widgets + CMake` 的 Windows 桌面工具，用来把本地 `release` 目录里的指定类型文件自动同步到多台远程主机共享目录。

## 已实现功能

- 可配置本地 `release` 目录
- 可新增、更新、删除远程主机
- 每台主机支持保存共享目录、账号、密码、是否启用
- 可选择同步类型，例如 `dll`、`exe`、`pdb`
- 支持手动“立即同步”
- 支持轮询本地目录变化后自动同步
- 每台主机都有独立进度条和状态颜色
- 远程完全一致显示绿色
- 不一致按差异程度显示不同深浅红色
- 共享不可达显示断线灰色
- 配置自动保存到程序目录下的 `sync_config.json`
- 支持手动检查 Gitee 上的新版本，并打开发行版下载页面

## 构建方式

请确保本机已安装 Qt 5.12.3，并使用和 Qt 安装包匹配的 MSVC Kit。

例如如果你的 Qt 是 `msvc2017_64`，那就要用对应的 MSVC 2017 工具链，或者在更高版本 VS 中安装 `v141` 工具集后再编译。

### 方式一：Qt Creator / qmake

```powershell
qmake RemoteReleaseSync.pro
```

然后用 Qt Creator 打开 `RemoteReleaseSync.pro` 编译，或者在已经初始化好的 MSVC 开发者命令行里继续执行对应构建命令。

### 方式二：CMake

如果你的环境里有 `cmake`，也可以使用：

```powershell
cmake -S . -B build
cmake --build build --config Release
```

生成的可执行文件名通常为：

```text
RemoteReleaseSync.exe
```

## 使用说明

1. 在“Release 目录”里选择本地编译输出目录。
2. 在“同步类型”里勾选需要参与同步的扩展名。
3. 在“远程主机配置”里输入共享目录、账号、密码并新增主机。
4. 勾选主机表格中的“启用”即可参与同步。
5. 点击“刷新状态”可以只检查一致性，不执行复制。
6. 点击“立即同步”会把勾选主机与所选类型执行同步。
7. 打开“检测到本地文件变化后自动同步”后，程序会按扫描间隔自动检测本地变化并同步。
8. 窗口标题显示当前软件版本，点击右下角“检查更新”可查看是否有新版；有新版时可以查看更新说明并前往下载。

## 软件更新发布

程序仅在点击“检查更新”时联网，异步检查最多等待 15 秒。更新信息固定读取公开仓库 `master` 分支根目录的文件：

```text
https://gitee.com/letmeseesee/remote-copying/raw/master/update.json
```

`update.json` 格式如下，三个字段均为字符串，版本号使用三段数字（例如 `1.10.0`）：

```json
{
  "version": "1.0.0",
  "notes": "新增手动检查更新功能。",
  "downloadUrl": "https://gitee.com/letmeseesee/remote-copying/releases"
}
```

发布步骤：

1. 更新 `src/main.cpp` 中 `setApplicationVersion` 的版本号，并同步修改 CMake 项目版本。
2. 生成完整发布包，包含 EXE、Qt DLL、平台插件及与当前 Qt 配套的 HTTPS/TLS 运行库；新增功能需要 Qt Network 模块。不要打包个人 `sync_config.json`。
3. 在 Gitee 创建对应版本的发行版，填写说明并上传 ZIP；确认使用者可以访问下载页面。
4. 发行包就绪后，将 `update.json` 的版本号、说明及 HTTPS 下载地址更新并提交到 `master`。仅修改本地文件或其他分支不会生效。
5. 使用者下载后先通过托盘菜单“退出”关闭程序，再替换程序文件，保留自己的 `sync_config.json`。

已有旧版没有更新检测入口，需要先手动安装一次含此功能的版本。网络失败、超时或版本信息格式错误会提示“检查更新失败”，不会被视为“当前已是最新版本”。

## 状态说明

- `完全一致`：本地和远端在所选类型下完全一致
- `不一致`：存在缺失、过期或远端多余文件
- `断线`：共享目录不可达或账号密码无效
- `同步失败`：执行复制时出现错误

## 说明

- 当前版本不会自动删除远端多余文件，只会补齐或更新文件。
- 密码保存在 `sync_config.json` 中，为明文保存，建议只在可信环境中使用。
