# RemoteReleaseSync 1.1.3 回归记录

验证日期：2026-11-23。环境：Windows 10 19044 x64、Qt 5.12.3 msvc2017_64、v142、Windows SDK 10.0.26100.0。本机工作区为 1600×860；通过 `QT_SCALE_FACTOR` 模拟缩放，未更改系统显示设置。

关联反馈：[Issue #2](https://github.com/UUxxXxxUU/SyncTool/issues/2)。提交者使用 1.1.2、Windows 11、2880×1440、系统缩放 200%、单显示器，点击最大化后窗口只占部分屏幕。

## 修改与本机复现

- `RoundedWindow::nativeEvent` 按所在显示器的原生工作区设置最大化边界，同时保留窗口最小、最大尺寸约束。
- `scheduleWindowBounds` 和 `applyMaximizedBounds` 在状态切换后核对边界，通过 `QWindow` 同步窗口与分层绘制缓冲区的尺寸，并保留校正前的正常位置、大小供还原使用。
- 新增原生尺寸消息、真实窗口边界、Qt 逻辑尺寸、渲染尺寸和还原位置检查；同步更新应用、CMake、测试版本、更新清单和窗口验收文档。

新增检查在本机发现：200% 模拟缩放时，窗口虽报告最大化，实际边界仍为 1520×846，而工作区是 1600×860。最终修复后，原生边界及渲染尺寸均为 1600×860，Qt 逻辑尺寸为 800×430，还原回到原来的位置和大小。这是本机观察结果，不作为 Windows 11 原场景已复现或已验收的结论。
